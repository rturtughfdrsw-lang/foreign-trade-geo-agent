## Purpose

This independent website is the control site for measuring how a conventional export-oriented B2B machinery website appears in search and generative systems before deliberate GEO changes are introduced. The intended baseline measurements include AI Visibility, Citation Rate, Share of Voice, Brand Mentions, Cited URLs, and Prompt Coverage.

The fictional brand is NovaCNC Machinery Co., Ltd. No content on the site should be treated as evidence of an operating factory, customer relationship, certification, award, sale, installation, review, or media report.

- Output-level tests for required routes, metadata, crawl files, internal links, article length, and baseline exclusions
- A build-time production-origin guard and explicit preview/production indexing policy

## Build and indexing policy

| Build context | `SITE_URL` | HTML indexing | robots.txt |
| --- | --- | --- | --- |
| `preview` (default) | Not required; no public origin metadata is emitted | All pages use `noindex, nofollow` | `Disallow: /`; no sitemap advertisement; empty sitemap |
| `production` | Required non-reserved HTTPS origin | The 13 baseline routes are indexable; 404 remains `noindex, nofollow` | `Allow: /` plus the production sitemap URL |

Production builds fail before generation when `SITE_URL` is missing, malformed, non-HTTPS, reserved/local, contains credentials, uses a port, or contains a path, query, or fragment.

## Verification contract

- `npm run check` and `npm run lint` validate Astro templates and TypeScript.
- A preview build plus `npm test` verifies preview noindex behavior, blocked robots, static HTML, schema boundaries, route generation, and internal links.
- A production build plus `EXPECT_INDEXING=true`, `EXPECTED_SITE_URL=<origin>`, and `npm test` verifies indexable HTML, canonical origins, production robots, sitemap entries, schema boundaries, and internal links.
- A production build without `SITE_URL` must fail with a clear guard error.
- The final implementation commit SHA is reported outside this document to avoid commit self-reference.

## Reproducibility notes

1. Record the final implementation commit hash and deployed origin used for every measurement run outside this baseline document.
2. Set `SITE_URL` to that origin before the production build.
3. Confirm canonical links, robots.txt, and sitemap.xml on the deployed site before collecting baseline observations.
4. Do not mix content, technical, or deployment changes into a measurement interval without creating a new experiment version.
5. Add later GEO features as isolated variables where practical and update the Present / Not Present lists.
6. Follow the version gates in [`experiment-roadmap.md`](experiment-roadmap.md); do not activate the reserved FAQ dataset or mutate the disclosure in place.
